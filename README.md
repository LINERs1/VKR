# EduAI — образовательная платформа с голосовым ИИ-ассистентом

> Руководство по запуску проекта **как есть** через Docker.
> Сценарий: вы скачали проект с GitHub (архивом или `git clone`) и хотите, чтобы **всё сразу работало** с уже заполненными базами данных.

---

## 🎙️ Главная фишка — голосовой ИИ-ассистент

Ключевая возможность проекта — **разговор с ИИ голосом** на русском языке. Пользователь нажимает кнопку звонка и общается с ассистентом как по телефону:

- 🔊 **Голосовой ввод** (распознавание речи) + **голосовой ответ** (синтез речи);
- 🧭 **Навигация голосом**: «открой курс Python», «следующий урок», «перейди в журнал»;
- 📖 **RAG-поиск по урокам**: «объясни, что такое функция» — ИИ ищет в материалах курса и отвечает с подсветкой нужного фрагмента;
- ✅ **Проверка ДЗ голосом** (для преподавателя): «проверь работу студента»;
- 📊 **Аналитика для админа**: «дай сводный отчёт по системе».

Голосовой режим работает на облачном сервисе **Ultravox** — для него нужен API-ключ (см. ниже). **Текстовый чат работает без Ultravox.**

> ⚠️ **Голосовой режим — главное, ради чего создавался проект.** Обязательно проверьте, что `ULTRAVOX_API_KEY` вписан в `ai_service/.env` (по умолчанию уже вписан в репозитории).

## 📋 Что это за проект

Три сервиса, работающие вместе:

| Сервис | Порт | Назначение |
|---|---|---|
| **Frontend** (Vue 3 + Nginx) | `80` | Веб-интерфейс платформы |
| **Platform backend** (FastAPI) | `8001` | Курсы, уроки, ДЗ, пользователи, авторизация |
| **AI service** (FastAPI) | `8000` | RAG-чат, **голосовой ассистент (Ultravox)**, навигация, проверка ДЗ |

В репозитории **уже лежат заполненные базы данных** и векторный индекс ChromaDB, поэтому после `docker compose up` вы получаете готовую платформу с курсами, уроками и обученным ИИ — без ручного наполнения.

### Что уже в базах (предзаполнено)
- **4 курса**: «Основы алгоритмизации», «Основы машинного обучения», «Веб-разработка с нуля», «SQL и базы данных»
- **51 урок** с полным текстовым содержимым
- **3 тестовых пользователя**: студент, преподаватель, админ (см. ниже)
- **Граф навигации** (66 узлов) для ИИ
- **Векторный индекс** ChromaDB для RAG-поиска по урокам

## 🚀 Быстрый старт (рекомендуемый путь)

### Требования
- **Docker** + **Docker Compose** ([установить](https://docs.docker.com/get-docker/))
- (рекомендуется) 8 ГБ ОЗУ и стабильный интернет

### Шаг 1. Скачайте проект

```bash
# Вариант A — через git
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> EduAI
cd EduAI

# Вариант B — распакуйте ZIP-архив и зайдите в папку
```

### Шаг 2. (Рекомендуется) Переключите ИИ на Gemini

Откройте файл `ai_service/.env` в текстовом редакторе и **замените две строки**:

```env
# БЫЛО (нужна Ollama):
LLM_PROVIDER=ollama
EMBEDDING_PROVIDER=ollama

# СТАЛО (облако, работает сразу):
LLM_PROVIDER=gemini
EMBEDDING_PROVIDER=gemini
```

Ключ `GEMINI_API_KEY` уже вписан в файл — больше ничего менять не нужно.

> Если хотите именно Ollama — оставьте `.env` как есть и выполните шаг 2-альтернатива ниже.

### Шаг 3. Запустите проект

```bash
docker compose up --build
```

При **первом** запуске Docker скачает базовые образы и соберёт 3 сервиса (5–15 минут в зависимости от интернета). Дальнейшие запуски — ~30 секунд.

В конце в консоли появятся строки:
```
platform_backend  | INFO: Platform Service started
ai_service        | INFO: 🚀 AI Service запущен: Голосовой помощник
ai_service        | INFO: ✅ Nav sync: N курсов совпадают между ИИ и платформой
frontend          | ... nginx
```

### Шаг 4. Откройте платформу

В браузере: **`http://localhost`** (порт 80, nginx).

### Шаг 5. Войдите под тестовой учёткой

| Роль | Логин | Пароль | Что доступно |
|---|---|---|---|
| Студент | `student1` | `password` | Курсы, уроки, голосовой ассистент, подсказки по ДЗ |
| Преподаватель | `teacher1` | `password` | Журнал, аналитика, ИИ-проверка ДЗ, мастерская заданий |
| Администратор | `admin1` | `password` | Всё, что у преподавателя + голосовые отчёты по системе |

## 🔧 Настройка провайдера ИИ

Все настройки — в `ai_service/.env`. Вот ключевые блоки:

### Вариант A: Gemini (облачный, рекомендовано для быстрого старта)
```env
LLM_PROVIDER=gemini
LLM_MODEL=gemini-2.5-flash
EMBEDDING_PROVIDER=gemini
EMBEDDING_MODEL=models/gemini-embedding-001
GEMINI_API_KEY=<уже вписан>
```

### Вариант B: Ollama (локальный, офлайн)
1. Установите [Ollama](https://ollama.com/) и запустите её.
2. Скачайте модели:
   ```bash
   ollama pull qwen2.5
   ollama pull nomic-embed-text
   ```
3. В `ai_service/.env`:
   ```env
   LLM_PROVIDER=ollama
   LLM_MODEL=qwen2.5
   EMBEDDING_PROVIDER=ollama
   EMBEDDING_MODEL=nomic-embed-text
   ```
4. ⚠️ **Особенность Docker**: контейнер не видит Ollama на `localhost`. Оставьте в `.env`:
   ```env
   OLLAMA_BASE_URL=http://host.docker.internal:11434
   ```
   (это уже настроено в `docker-compose.yml` через `extra_hosts`).

### Вариант C: OpenAI
```env
LLM_PROVIDER=openai
LLM_MODEL=gpt-4o-mini
EMBEDDING_PROVIDER=openai
OPENAI_API_KEY=sk-...
```

### 🎙️ Голосовой режим (Ultravox) — ОБЯЗАТЕЛЬНО для голосового ИИ

> Это **главная фича проекта**. Без `ULTRAVOX_API_KEY` голосовой звонок работать не будет — останется только текстовый чат.

Голосовой ассистент работает через облачный сервис [Ultravox](https://ultravox.ai/) (Realtime Voice AI). В `ai_service/.env`:
```env
ULTRAVOX_API_KEY=<уже вписан в репозиторий>
ULTRAVOX_VOICE_ID=<уже вписан>
ULTRAVOX_MODEL=ultravox-v0.7
ULTRAVOX_VOICE_SPEED=0.85
```

**Как это работает:**
1. Фронт вызывает `POST /api/ultravox/call` → AI-сервис создаёт звонок в Ultravox и возвращает `joinUrl`.
2. Браузер подключается к `joinUrl` через WebRTC — начинается голосовой диалог.
3. Во время разговора Ultravox вызывает tools ИИ-сервиса: `queryKnowledgeBase` (RAG-поиск), `navigatePage`/`openLesson` (навигация), `reviewHomework` (проверка ДЗ), `adminGetReport` (отчёты для админа).
4. `/api/ultravox/rag` — публичный endpoint, его дёргают **серверы Ultravox** (не пользователь), для поиска по урокам прямо во время разговора.

**Проверка ключа:**
```bash
# После запуска — список доступных голосовых моделей:
curl http://localhost:8000/api/ultravox/models -H "Authorization: Bearer <JWT>"
```

> 🔴 Если `ULTRAVOX_API_KEY` пустой или невалиден — голосовой звонок вернёт ошибку `ULTRAVOX_API_KEY not configured`. Получить свой ключ можно бесплатно на [app.ultravox.ai](https://app.ultravox.ai/).

**Без Ultravox** работают: текстовый чат, RAG-поиск, подсветка фрагментов, TTS (озвучка текста). Не работает только живой голосовой диалог.

## 🏗️ Архитектура и порты

```
                ┌─────────────────────────────────────┐
   Браузер ───► │  Frontend (nginx:80)                │
                │  раздаёт статику + проксирует /api   │
                └──────┬──────────────────────┬───────┘
                       │ /api (к платформе)    │ /api (к ИИ)
                       ▼                      ▼
     ┌─────────────────────────┐  ┌──────────────────────────┐
     │ Platform backend (8001) │  │ AI service (8000)        │
     │ • курсы, уроки, ДЗ      │  │ • RAG-чат                │
     │ • auth (JWT)            │◄─┤ • голосовой ассистент    │
     │ • users                 │  │ • навигация (граф)       │
     │ SQLite: platform.db     │  │ • проверка ДЗ            │
     └─────────────────────────┘  │ SQLite: app.db           │
                                  │ ChromaDB: chroma_db/     │
                                  └──────────────────────────┘
```

- **Platform** отдаёт `GET /api/courses` → AI-сервис тянет оттуда данные для графа навигации.
- При старте AI-сервиса сверяется граф с курсами платформы и **автоматически** подтягивается недостающее (`auto_pull`).
- Поэтому базы всегда синхронны — ручная настройка не требуется.

## ✅ Проверка, что всё работает

После запуска откройте в браузере или выполните в терминале:

| Что проверить | URL / команда | Ожидаемый результат |
|---|---|---|
| Платформа открылась | `http://localhost` | Главная страница с курсами |
| Платформа жива | `http://localhost:8001/api/health` | `{"status":"ok",...}` |
| ИИ-сервис жив | `http://localhost:8000/api/health` | `{"status":"ok",...}` |
| Курсы отдаются | `http://localhost:8001/api/courses` | JSON-массив с 4 курсами |
| Граф навигации ИИ | `http://localhost:8000/api/navigation/dynamic-nodes` | Список узлов `/courses/...` |

**Проверка чата (главное):**
1. Войдите как `student1` / `password`.
2. Откройте курс «Основы алгоритмизации».
3. Нажмите на иконку ассистента (правый нижний угол).
4. Спросите: *«Объясни, что такое переменная в Python»* — ИИ должен ответить по материалам урока.

**Проверка голосового режима (ГЛАВНАЯ ФИЧА):**
1. Войдите как `student1` / `password`.
2. В виджете ассистента нажмите кнопку **голосового звонка** (📞, не текстовый ввод).
3. Дайте разрешение на микрофон в браузере. Дождитесь приветствия ИИ.
4. Скажите голосом: *«Какие есть курсы?»* — ИИ ответит вслух.
5. Скажите: *«Открой курс по алгоритмам»* — ИИ перейдёт на курс.
6. Скажите: *«Объясни, что такое переменная»* — ИИ найдёт фрагмент в уроке, ответит и **подсветит** его на странице.

**Проверка голосового режима для админа:**
1. Войдите как `admin1` / `password`.
2. Начните голосовой звонок.
3. Скажите: *«Дай аналитический отчёт по системе»* — ИИ спросит тип (сводный/детальный), затем зачитает ключевые цифры.

> Если звонок не начинается — проверьте `ULTRAVOX_API_KEY` (см. [🎙️ Голосовой режим](#-голосовой-режим-ultravox--обязательно-для-голосового-ии)) и что браузер имеет доступ к микрофону.

## 🛠️ Управление контейнерами

```bash
# Запуск (с пересборкой после правок кода)
docker compose up --build

# Запуск в фоне
docker compose up -d --build

# Посмотреть логи конкретного сервиса
docker compose logs -f ai_service
docker compose logs -f platform_backend

# Остановить
docker compose down

# Полный сброс (УДАЛИТ историю чата и индекс! базы пересоздадутся из seed)
docker compose down
# затем удалить volume-файлы БД, если нужно начать с нуля:
del ai_service\app.db
rmdir /s /q ai_service\chroma_db
del platform_service\backend\platform.db
```

> ⚠️ Файлы БД примонтированы в `docker-compose.yml` как volumes (`./ai_service/app.db:/app/app.db`). Это значит: **данные переживают перезапуск контейнеров** и хранятся на хосте. Если удалить эти файлы — при следующем старте БД пересоздастся из `seed.py` (стандартные курсы/уроки/пользователи), но **история чата и пользовательские данные пропадут**.

## 🐛 Частые проблемы

### 1. `docker compose up` падает с ошибкой порта 80
Порт 80 занят другим приложением (Skype, IIS, другой nginx).
**Решение:** в `docker-compose.yml` поменяйте `"80:80"` на `"8080:80"` и открывайте `http://localhost:8080`.

### 2. ИИ-сервис не отвечает / отвечает «материалы курса не найдены»
- Проверьте `ai_service/.env`: провайдер указан верно, ключ есть.
- Если Ollama: убедитесь, что она запущена и модели скачаны. Из контейнера проверьте: `docker compose exec ai_service curl http://host.docker.internal:11434/api/tags`.
- Если Gemini/OpenAI: проверьте интернет и валидность ключа.

### 3. Голосовой режим не подключается / нет звука
Это **главная фича проекта** — проверьте по чеклисту:
- ✅ `ULTRAVOX_API_KEY` вписан в `ai_service/.env` (по умолчанию в репозитории он есть).
- ✅ Ключ валиден: проверьте `curl http://localhost:8000/api/ultravox/models -H "Authorization: Bearer <JWT>"` — должен вернуть список моделей. Если 401/403 — ключ невалиден.
- ✅ Браузер **разрешил доступ к микрофону** (значок 🎤 в адресной строке).
- ✅ Не запущен ли локально другой процесс на порту, который перехватывает WebRTC.
- ✅ В Docker-сети фронт проксирует `/api/ultravox/call` к AI-сервису — проверьте `frontend/nginx.conf`.

Без Ultravox текстовый чат и TTS работают — недоступен только живой голосовой диалог.

### 4. `ECONNREFUSED` / AI не видит платформу
В Docker-сети сервисы общаются по **именам контейнеров**, не по `localhost`:
- `ai_service/.env` → `PLATFORM_SERVICE_URL=http://platform_backend:8001`
- `platform_service/backend/.env` → `AI_SERVICE_URL=http://ai_service:8000`

Эти значения уже прописаны в `docker-compose.yml` (переопределяют `.env`), трогать не нужно. Проблема возникает только если вручную меняете переменные.

### 5. Логи показывают `⚠️ Nav sync: платформа недоступна`
AI-сервис стартует быстрее платформы и не достучался. Это **нормально при первом старте** — при следующем запросе навигации или перезапуске синхронизация пройдёт. Граф навигации уже заполнен в `app.db` (включено в репозиторий), так что чат работать будет.

### 6. После удаления БД курсы не появляются
Убедитесь, что платформа стартовала раньше проверки синхронизации. Перезапустите `ai_service`:
```bash
docker compose restart ai_service
```
В логах должно появиться `✅ Авто-загрузка завершена`.

### 7. Время сборки очень долгое
Первый `docker compose up --build` скачивает образы Python/Node/nginx и ставит зависимости. Дальнейшие сборки используют кэш Docker. Если правите только один сервис:
```bash
docker compose up --build ai_service      # пересобрать только ИИ
```

2. Сверьтесь с таблицей [Проверка](#-проверка-что-всё-работает)
3. Убедитесь, что `.env` файлы настроены (см. [Настройка провайдера ИИ](#-настройка-провайдера-ии))
4. Для полного сброса — удалите файлы БД (см. [Управление контейнерами](#-управление-контейнерами)) и запустите заново

**Контакты/поддержка:** создайте issue в репозитории GitHub с логами `docker compose logs`.
